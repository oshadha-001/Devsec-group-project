# Oshadha IT24103920 SQL injection and architecture

Planned owner: Oshadha. Source changes prepared with Codex; actual student review and PR remain to be recorded.

## Root cause and scope
At upstream security level 0, user-info.php passes username/password into SQLQueryHandler::getUserAccount. The original function concatenates both into a SELECT expression. Input can change the query meaning and expose other synthetic accounts. This is CWE-89, STRIDE tampering/information disclosure; likelihood 3 and impact 3 give risk 9 on a 3x3 scale because the lookup is reachable and can return multiple accounts.

The fix binds two string parameters using mysqli prepare/bind_param. It rejects non-string and excessive-length inputs. It applies at every security level and preserves the returned mysqli result expected by user-info.php. Other SQL methods and plaintext password storage are residual risks, not claimed fixed.
